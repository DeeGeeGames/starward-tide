# Galaxy Conquest

A touch-first, single-player real-time strategy game. Expand between planets, choose troops, ships, or defense platforms, and conquer the rival. Battles take place within a single star system.

Bun serves and bundles HTML/TypeScript/CSS directly. ECSpresso 0.24.1 runs the tactical simulation; PixiJS 8.19.0 renders units beneath DOM planets and controls.

The [current game design](docs/game-design.md) documents star system combat, production, victory, persistence, and remaining playtest questions. Technical evidence is in [performance diagnostics](docs/performance-diagnostics.md), [renderer migration](docs/renderer-migration.md), and [viewport culling](docs/viewport-culling.md).

```sh
bun install --frozen-lockfile
bun run dev
```

Open http://localhost:3000. `bun run check` runs lint, simulation tests, strict TypeScript checks, and a production build into `dist/`.

GitHub Pages publishes the production build at https://david0178418.github.io/galaxy-conquest/. The [deployment workflow](.github/workflows/deploy.yml) runs checks, builds, and deploys on pushes to `master`; it can also be run manually from the Actions tab on `master`. Repository Settings → Pages must use **GitHub Actions** as the build source. Bundled asset URLs are relative, so the same build works under `/galaxy-conquest/` and at a domain root.

The production build is an installable PWA. Open the standalone HTTPS site and use your browser's **Install app** command; on iPhone/iPad, use Safari's **Share → Add to Home Screen**. It opens in its own window using the existing GC icon. Installation availability depends on the browser; embedded player cards should be opened as the standalone site first.

After the first online visit finishes caching, the game can reopen and play offline, including local profiles and saves. New releases download in the background. When ready, an **Update available — reload** button lets you activate the release and reload that window; finish or save your game first. Other open game windows are not automatically reloaded. Without clicking, updates activate after all game windows/tabs close. Saves remain in IndexedDB and retain the browser/site storage limits described below. Workbox generates the offline cache from build assets; source maps and the social poster are excluded. PWA registration is production-only, so `bun run dev` does not install a worker. Serve `dist/` over localhost or HTTPS to test installation/offline behavior.

The page includes X player-card metadata intended to embed the game in a post, using [assets/x-card.jpg](assets/x-card.jpg) as the poster. Metadata and a successful build alone do not verify live inline playback on X. Use the deployed standalone URL, including the trailing slash, when checking card behavior. An embedding host must permit framing.

## Skirmish and local profiles

The title screen offers up to 10 local profiles. On first use, a **Player** profile is created and selected automatically so you can start immediately. You can rename it or create another profile. Each profile has one ongoing star system battle: **Continue** restores its saved map and game state paused, and **New conquest** opens setup and asks before replacing progress. Rename keeps progress; deleting a profile requires confirmation and removes only that profile. Choose **Save** in the game menu or rely on periodic autosaves, including while paused. The menu retains the full save timestamp; save failures stay visible during play, including on phones.

Starting a new conquest or replacing the current map requires confirmation when it would replace progress. From **New conquest**, use **01 Galaxy** to choose **Small** (12 worlds), **Medium** (18), or **Large** (30), inspect the preview, and use **Generate another map** to reroll it. **02 Opposition** configures the AI opponents, difficulty, and style. **Begin conquest** launches that exact layout with one world and three ships per side. The optional **Carriers** skirmish setting is off by default; enabling it adds one carrier per side with 20 crew and three docked ships. The current carrier production rate is provisionally set to 25% of the standard home-world rate; it remains unvalidated for balance. This is a standalone star-system feature; there is no campaign layer. Existing saves without carriers remain compatible. Generated worlds have mirrored positions and resources for equal expansion opportunities, with at least 216 units between centers. **Restart map** replays the same layout.

Choose **Conquest**, **Center race**, or **Crossing race** in setup. Both races automatically include carriers. Center race has one shared destination near the middle, equally distant from the starting carriers. Crossing race gives each side a destination near the opposing start, with equal carrier travel distances. Destinations are shown in the preview and on the battlefield. Select your carrier and use **Move to destination**, or click empty space to choose a route. The first carrier center to enter its destination’s dashed zone wins; an exactly simultaneous finish is a draw. Either carrier can score for its current owner after capture. Blockade does not stop carrier movement or arrival; capture the carrier to interrupt its route. Eliminating every rival holding remains a fallback victory. Modes, destinations, courses, and results survive saves and restarts; older saves remain Conquest.

Before starting, choose **Relaxed**, **Standard**, or **Hard** opponent difficulty and an **Expansionist**, **Aggressive**, **Defensive**, or **Random** style. Relaxed decides about every 5.6 simulation seconds and waits for larger attack margins; Standard retains the existing 2.8-second decisions and attack rules; Hard decides about every 1.4 seconds and commits leaner attacking fleets. Difficulty grants no production, movement, health, or damage bonuses. Expansionist favors neutral worlds, Aggressive favors player worlds, and Defensive builds two platforms on each ordinary world before committing its troops to expansion, with a stronger preference for neutral worlds. Carriers cannot build platforms and retain their local defense behavior. These are target preferences, not guarantees to ignore nearby opportunities or threats.

Random chooses one of those styles when the conquest starts. The game menu shows the actual difficulty and style. Saves, Continue, and Restart map retain them; older saves use Standard / Expansionist. The prototype lab's AI toggle remains independent of difficulty and style.

Profiles and conquests use IndexedDB in the current browser and site. They do not sync between devices, browsers, hosting origins, or embedded and standalone versions. Clearing site data or browser storage eviction can remove them. Embedded browsers may block or partition storage; open the standalone game if saves are unavailable. There is no account, cloud backup, or export/import.

Save validation has format safety bounds independent of gameplay tuning: at most 100,000 troops per planet or cargo units per transport; production-rate values up to 10,000 and production progress below 10,000; map dimensions up to 10,000; unit positions within ±20,000; and planet radii up to 1,000. A save outside those bounds cannot be continued; validation leaves the stored profile data unchanged.

The star map fills the viewport. Drag to pan; scroll or pinch to zoom around the pointer or touch midpoint. Horizontal scrolling pans sideways. Focus the map and use arrow keys to pan, Space to pause/resume, or Home to fit the map. The Fit map button also restores the full view; clearing selection and opening menus preserve zoom. Use Fullscreen on the title screen or in the game menu where supported. The top-left cluster shows holdings and elapsed time; Orders, Pause, and the menu sit at the top right. With carriers enabled, holdings include both worlds and carriers. Selecting a holding opens a command rail on desktop or a bottom sheet on portrait phones. Narrow landscape uses a side rail. Selection framing keeps the selected holding clear of the controls without resetting zoom. Labels keep a readable size at zoom-out; crowded names yield to selected/owned labels and remain available through selection, hover, or keyboard focus.

The Command Horizon interface uses a full-screen title, large focusable menu choices, and two setup steps. The command panel opens with forces and **Dispatch**, **Production**, and **Orders** actions. **Dispatch** reveals amount and unit filters, followed by **Choose destination**. **Production** is available only for owned holdings. **Back** returns to the command overview before clearing the source selection. The chevron collapses the controls on every screen size, and close/collapse controls stay reachable while the panel scrolls. Save, fullscreen, restart, new game, profiles, scenarios, pace, and help are in the game menu. Small screens hide the wordmark and routine save timestamp; below 360px the clock is also hidden. Save errors remain visible.

Tap or left-click a blue planet or carrier to select it. Hold or right-click a destination to send units. For keyboard dispatch, press **D** after selecting sources, then tap, click, or focus a destination and press Enter. The command panel clears while choosing, with the source and available launch counts kept in view. **Cancel**, Escape, or right-clicking empty map space cancels destination choice and any pending touch hold without clearing the sources. The default amount is 50%; 25%, 100%, ships-only, and troops-only are also available. Preview counts use the same rounding and blockade rules as dispatch. Platforms never travel.

For direct dispatch, hold an entity for 500 ms on touch or right-click it with a mouse. A visible outline marks a pending hold. Dragging, pinching, zooming, cancelling a touch, opening a menu, or losing window focus cancels it. With one owned carrier selected outside destination mode, click empty map space to set its course. **Launch docked ships here** sends the selected share into local space, including during blockade. Multi-select gathers sources; finish selection before dispatch. Shift-click also adds or removes sources. Tap a selected source again or use Clear selection to deselect; clicking empty map space clears ordinary selections. Escape closes an open menu or Orders before clearing selection. Friendly orbital ships above an enemy surface remain valid ship-only sources, and their enemy surface stock is excluded from player force totals.

Troops capture surfaces; ships and defense platforms fight in orbit. Troops launch in free, disposable transports carrying up to 10 each. Ships travel at 23.75 world units per simulation second; transports travel at half that speed (11.875), so escorts can arrive first. Carriers travel at 5.9375 units per second: 25% of ship speed and half transport speed. Ships and transports sent to a moving carrier update their intercept as it moves. Ships can intercept hostile travelers within 48 units; transports take fire and keep moving. Landings wait for hostile orbital resistance to clear. A dashed hostile ring means blockade, preventing departures from ordinary planets while production continues. A carrier can keep moving and launch its docked ships during blockade, but docking waits until hostile resistance clears. These permissions do not change ordinary planet departure restrictions. Carriers cannot be damaged or destroyed, have no platforms or crew/docked-ship capacity limits. Select **Bombard planet**, then a hostile or defended neutral world: the carrier approaches orbit and charges for 20 simulation seconds before wiping surface troops and making the planet neutral. Hostile ships and platforms cannot stop the charge or shot; boarding the carrier, moving it, or cancelling the attack stops it. Friendly capture of the target also cancels the shot. Orbital forces survive, and occupation still requires a normal troop landing. The charge countdown and target ring remain visible during pause; saves retain the target and partial charge. Boarding transfers the carrier and all docked ships and stops its movement; ships already launched remain independent. An owned carrier counts as a surviving holding for victory. Orbital control alone never captures a planet or carrier. See [tactical rules and tuning](docs/game-design.md#tactical-rules) for targeting, arrival grace, capture, and production details.

The **Skirmish settings** contains a normal AI skirmish, an established blockade, and a defended invasion. The skirmish starts with the rival AI on. The blockade and invasion labs start with AI off; enable it on those labs when useful. In carrier skirmishes, the AI moves carriers to bombard worlds, retains their crew, deploys escorts, and launches docked ships locally to contest blockaders. It attempts boarding retaliation against bombardment threats and sends occupation forces after neutralization. In either race, it navigates toward its assigned destination, keeps carrier crew and docked escorts aboard for defense, and prioritizes attacks on player carriers. Restart resets the scenario; pace changes persist. Pause freezes movement, production, combat, and AI while keeping map navigation, selection, orders, and production changes available. Orders allocate units immediately, so repeated sends use the remaining stock; movement and production progress continue on resume, without catching up paused time. Open **Orders** beside Pause to view active dispatches. The drawer shares the command panel’s space and filters incoming, outgoing, and returning routes to the selected planet (or selected sources). **Show all** keeps the planet selection while showing every route; changing the selection restores automatic filtering. Select an order row to highlight its route without changing the selected planet. **Cancel launch** releases a paused dispatch’s reserved ships and troops before departure. **Recall** turns surviving escorts and loaded transports around at their current positions and sends each back to its own departure world; recalling during pause sets the course but movement waits for resume. Returning orders remain visible until arrival. Waiting transports and their escorts can be recalled before landing; completed arrivals leave the drawer. If a departure world changes hands, normal arrival/combat rules apply there. Switching tabs pauses tactical simulation automatically; it resumes on return if it was running before the tab was hidden and the controller is not the active input. Controller-driven games require deliberate resume. In Conquest, win when your rival owns no planets or carriers; bombardment can neutralize a final planet without occupying it.

Standard-mapped browser gamepads are supported. Press **A** or **Start** to claim a controller, then release the controls. Menus use the D-pad or left stick, **A** selects or changes a setting, and **B** goes back. In a match, the left stick moves the targeting cursor, the right stick pans, **LT/RT** zoom, and **LB/RB** cycle worlds and hostile fleet markers. **A** selects a world, confirms a target, or sets a selected carrier's course on empty space. **X** opens dispatch settings, **Y** toggles multi-select, **Start** pauses/resumes, and **Back/View** opens the game menu. Use **B** to leave a command panel and return to the map while retaining sources; another **B** clears selection. The right stick scrolls long menus and help. Controller prompts follow the active input; pointer, keyboard, and touch remain available.

Only a deliberately claimed controller controls the game. Disconnect or loss of focus pauses a controller-driven match; reconnect, release the controls, claim with A/Start, and press Start again to resume deliberately. Reconnecting does not send units or resume on the claim press. Gamepad support depends on the browser exposing a standard mapping; physical controllers, TV-distance readability, and touch comfort still require device playtesting.

The browser smoke scripts accept an existing Playwright installation through `PLAYWRIGHT_MODULE` and a running game through `GAME_URL`. Run `node scripts/playtest-command-horizon.cjs` for the simulated controller journey, or `node scripts/playtest-polish.cjs` for mouse/keyboard/touch regressions. These checks complement `bun run check` and do not establish physical-device acceptance.

The [design reference](docs/game-design.md) includes map sizes, starting forces, AI behavior, tuning values, implementation entrypoints, and acceptance limits. There is no networking, audio, cloud sync, or arbitrary mid-flight retargeting. Physical-device touch comfort, combat readability, balance, and match feel require playtesting.
